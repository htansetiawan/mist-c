# M4: subgame core and integration contract

Astra, 2026-10-11. Written from [Obscuro v2](https://arxiv.org/html/2506.01242v2), especially B.2, C.1–C.3, C.6 and Figure 9. No third-party engine source was consulted.

## Implemented

- `gadget_build`: Resolve and Maxmargin root layers over **one** copied continuation forest. The two modes share continuation infosets and solver arrays. Roots within an opponent information set are sampled using normalized chance-times-our reach. Root-group Resolve probabilities use `0.5 * (normalized y(J) + 1/m)`; `y(J)` is counted once per infoset. An all-zero y vector falls back to uniform, explicitly.
- `gadget_blueprint_stats`: fixed-profile conditional continuation values and separate counterfactual/opponent reach arrays. This does not replace the opponent with an omniscient best response.
- `gadget_group_blueprint`: conditional values at a root group. Checks that the opponent's own sequence reach agrees across its histories, as perfect recall requires.
- Gift and new-world alternate helpers. **All utilities are player-zero values.** Figure 9 line 8 says `effective_alternate = u(x,y|J) - gift`. Both gadget continuations therefore use `raw_value - effective_alternate`. Resolve's centered exit value is zero. This yields the truncated-margin objective without changing its strategies. A nonzero-alternate analytic fixture catches a wrong offset sign.
- `kluss_select`: order-2 frontier closure from the current own-history infoset plus directly connected opponent-history groups. It does not take the transitive closure. Sorting/binary search costs O(R log R) for R frontier histories; forest copying is O(nodes + edges + roots).
- The retained downward closure leaves off-current-infoset player-zero nodes **unfrozen**. Their choices can improve in the next solve.
- `KlussBlueprint`: owned structural/history/behavior snapshot. No accumulated regret, last-regret prediction or average-strategy counts are transferred. `gadget_seed_blueprint` seeds only the fresh initial prediction with the previous behavior; cumulative regrets start at zero. The first visited update replaces that prediction with the instantaneous regret. Putting the policy into cumulative regret would leave an unintended persistent prior.
- Explicit rejection of overlapping root subtrees, invalid probability distributions, zero counterfactual support, nonfinite inputs, and downstream opponent infosets that forget which root group they observed.

## Automatic controller and blueprint preparation

`gadget_iteration` implements the Figure 10 alternating update over one shared continuation. Both the Maxmargin selector and the per-group Resolve entry minimizers learn every iteration. Player zero uses effective opponent root reach

```
w[J] = pmax * alpha[J] * enter[J] + (1-pmax) * maxmargin[J]
```

These weights need not sum to one: **do not renormalize them during CFR**. Player one examines each group counterfactually even if its current root weight is zero. Unvisited own infosets retain their last predictive regret. Workspace storage grows when new infosets are appended; callers must run `game_grow` before the next solve iteration. Last-iterate behavior remains in the shared Game; `max_enter`, `active_mass` and `root_weight` expose the actual controller state. `game.root` selects a fixed gadget only for diagnostic evaluation; it does not select the adaptive policy's objective.

`kluss_prepare` now turns a valid raw blueprint and a supplied history frontier into its **carried** gadget. It selects I², groups by full opponent history, computes conditional alternate values and opponent-only reach, and calculates gifts before pruning. Gift increments use action values aggregated over the opponent's information set; computing a different gift separately on each hidden board is incorrect. Sorting groups avoids rescanning the frontier for every group: work is linear in the tree/slots plus O(R log R) for R frontier histories. It seeds fresh minimizers from blueprint behavior, and leaves a previously prepared game unchanged on failure.

This helper does not identify the correct chess frontier or add newly sampled states. Those remain engine responsibilities, and must not be simulated by matching only a board hash.

## Capturing an adaptive solve

Use `kluss_blueprint_capture_gadget`, not a plain capture of `gadget.game`.
The snapshot keeps a forest rooted at the per-group chance nodes, seeds each
with counterfactual reach 1 and the **effective** opponent root reach from
Figure 10, and restores raw utilities throughout its reachable leaves. This
includes leaves appended after the original gadget was built. Copying only the
initial source-node map would miss them. The original gadget is unchanged.

Call `kluss_blueprint_stats` on a saved snapshot. Its forest boundaries replace
`tree.root` as the reach origins. Old selector/entry/exit nodes may remain in the
owned structural copy for stable node IDs, but are outside the forest: they
contribute neither reach nor gifts. All real opponent actions below the boundary
still contribute to gifts. A zero-probability opponent group retains its positive
counterfactual support.

`active_mass` preserves the possibly subunit continuation reach. The snapshot's
`expected_value` is the raw continuation mean conditional on entry, rather than
a centered margin or an artificial exit payoff. This value is over the retained
forest: if the engine needs the value conditional on its **current** I, which can
be smaller than I², it must additionally condition the raw values on that I and
log zero-reach cases. No convention here manufactures reach for off-policy moves.

## Experimental chess adapter

`src/m4search.c/.h` now integrates the generic core into a persistent chess
context. `src/m4main.c` is a separate front end; build it with
`make build/mist-m4`. The active `src/main.c`, `src/gtcfr.*`, shared headers and
Fable's Stockfish work are unchanged. This is a review checkpoint, **not an arena
candidate**.

The context records every view and every actually played own move. Payloads keep
Position, complete own/opponent history hashes, ply, live/terminal status and the
fresh-root knowledge scope. A same-ply frontier retains I and opponent-connected
off-I histories, restores raw scores before recombination, and captures actual
adaptive root reaches for the next turn. New root samples have separate
perfect-information opponent scopes. The current-I reference value is conditioned
on actual entry mass; zero own reach after a forced off-policy move is reported,
not replaced by invented positive reach.

Root sampling uses a weighted exponential-race heap in O(P log K), with sorted
carried-state exclusions. The opt-in `MIST_M4_WITNESSES=1` experiment adds
highest-weight witnesses of uncovered immediate king-loss actions, then fills
remaining slots with weighted samples. It costs O(P A + A log A), with A <= 256,
checks a 20%-of-budget scan deadline, and explicitly reports incomplete scans.
It does not estimate posterior probabilities, recover already missing belief
states, or guarantee safety. **It remains off:** increased hazard coverage did
not fix the critical cold replay.

`make test_m4` includes both the six generic suites and the new chess/sampling
suites. They test both colors, protocol phase/history conformance, actual carry
and off-I retention over four decisions per color, bounded nodes, a fifty-move
draw, and a rare hidden-slider witness at identical observations. The fixed-tree
integration probe deliberately prints a negative result: static alternate
-0.970012071 exceeds the best available child -0.991486640 in the dangerous
world. No mixture can meet that alternate. The resulting purified move can lose;
this is not mislabeled as a safety-test pass.

### Remaining gates and approximation limits

- Leaf values are the in-process C evaluator, kappa=1. M4 does not yet use
  Stockfish. Fable's UCI reader needs a total request deadline before it can be
  safely put inside this adapter's budget.
- Tree growth retains the original GT-CFR strategy/visit-bonus approximation,
  not the paper's empirical-variance/value PUCT scheduler.
- Future moves are view-proven actions. This deliberately omits ambiguous
  en-passant opportunities. Root histories enforce action-set consistency.
- Belief deduplication keeps one opponent history per board and excludes the
  halfmove clock from its key; the adapter cannot restore discarded histories.
- Capture, king-exposure, no-move, and fifty-move terminals are handled. The
  search does not yet model full historical threefold repetitions or apply the
  legacy front-end repetition exclusion. Do not ship until addressed/measured.
- Setup/solve/snapshot share a soft deadline. Deep copying and one CFR traversal
  are not interruptible. Deadline and memory behavior need full-clock gates.
- Purification follows the current Resolve/Maxmargin mode. Mixed-strategy
  guarantees cannot be attributed to a purified move.
- Diagnostics (`MIST_M4_DUMP_PLY`) run after selection and add wall time. Do not
  use diagnostic-enabled timings as tournament-clock measurements.
- The 24 deaths + 24 survivals, corrected five-death/earlier-prevention corpus,
  and paired 180+2 match gates remain incomplete. No Elo claim is supported.

The five final v26 loss positions contain **two unavoidable immediate losses**:
7crrql6k ply36 (23 legal moves, zero survivors) and zn8m31zt ply47 (14, zero).
Study their earlier own turns, plies34 and45. The other finals have26,6,6 safe
moves. This was enumerated with the official referee, including repetitions;
truth is used only by the external diagnostic, never by the policy.

## Correctness checks

`make test_m4` runs:

- A 99% ordinary / 1% fatal world game. Plain expected-value PCFR+ chooses the risky action (value 0.98); both gadget variants choose the safe action with zero measured gadget exploitability.
- A game with unequal nonzero alternate values and an analytic 50:50 mixed equilibrium. Last-iterate output reaches 0.5; computed exploitability is numerical zero.
- An infeasible-margin game with different analytic answers: Resolve chooses action zero with probability 0.75; Maxmargin chooses 7/17. Both converge to numerical-zero gadget exploitability.
- Complete-frontier Kuhn poker: conditional blueprint alternate values, distinct hidden cards, full-game opponent best-response evaluation after replacing player zero's strategy. Both modes preserve the converged blueprint's 1/18 opponent BR value. This is a full-cut fixture, not a safety proof for truncated KLUSS.
- A counterfactual reach test where a zero-probability opponent action still has nonzero opponent-counterfactual support.
- A distance-two frontier world that must be excluded, an off-current-infoset node that must be re-optimized, deep-copy independence, and failed snapshot replacement preserving the old blueprint.
- Bad root/weight inputs and fresh solver-state checks.
- A one-iteration adaptive-controller oracle: root weights 0.1996 and 0.2232, total 0.4228; exact own instantaneous regrets and alternating opponent/root updates.
- Adaptive infeasible/positive-margin/rare-trap fixtures, plus leaf-value revisions on the same minimizers to exercise Resolve → Maxmargin → Resolve transitions.
- Zero-root-mass opponent replies still learn; pruned own predictions remain unchanged; an 81-action infoset appended after all root gadget infosets grows and solves correctly.
- Adaptive full-cut Kuhn retains the full-game opponent BR value 1/18. Its fixed-Resolve diagnostic gap is nonzero (~0.01114); this is not reported as an equilibrium of the adaptive objective. The original fixed-gadget fixtures still have numerical-zero gaps.
- Blueprint preparation preserves one-hop closure, raw source data and fresh behavior seeds. A hidden-world shared-infoset fixture verifies the aggregate gift of 1.2 (not board-local values 0.75 and 1.5). Invalid metadata preserves the previous prepared object.
- Two successive adaptive captures: root weights 0.1996/0.2232 remain unnormalized; real opponent action reaches become 0.0499/0.13392; gifts are 3/2 from those real actions only. A newly expanded leaf returns to raw value 8 through two distinct utility offsets. A zero-probability opponent group keeps its CF support. Overlapping forest boundaries and invalid snapshot replacement are rejected.

## Replay modes and evidence boundaries

`src/main.c`'s current `MIST_FORCE_MOVES` branch plays the recorded moves and continues **without searching**. Consequently, the existing single-decision replay scripts would present M4 with a cold tree at the target position. That can evaluate a fresh-world gadget, but cannot test blueprint carry-over or retained off-current-infoset worlds.

The new frontend implements `MIST_REPLAY_WARM=1` to search before playing each
forced prefix move. It records the actual move, even if the search wanted
something else. `MIST_REPLAY_PARENTS=N` (replay-only, minimum2000) fixes belief
thinning to make policy comparisons independent of machine load. Ordinary arena
clock control is unchanged. `MIST_SAMPLES=N` sets the root sample target.
`MIST_REPLAY_BELIEF_DUMP=path` exports the observation-derived belief **after**
choosing the target move; the external Python checker compares it with truth and
removes the temporary export. No true board enters the bot.

`astra-submissions/tools/m4_replay_probe.py` in IAmAVirus reports exact protocol
prefixes, legality, unavoidable-loss cases, true-board/tactical-state/full-state
coverage, action risks under the final gadget, and separate cold/warm results.
On-policy paired matches remain necessary: forced recorded moves can have zero
blueprint reach, and recorded continuations need not resemble the candidate's.

Address/undefined-behavior/leak sanitizer runs cover all six M4 fixtures at this revision. The sandbox prevents LeakSanitizer's process inspection; the same binaries were therefore run on the host with leak detection enabled.

Generic exact gadget games have the usual conditional safety premises. Obscuro's approximate depth-limited 2-KLUSS does not inherit a general full-game safety guarantee (paper C.6). These fixtures establish arithmetic, topology and solver behavior, not chess Elo.
