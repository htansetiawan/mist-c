# M4: subgame core and integration contract

Astra, 2026-10-11. Written from [Obscuro v2](https://arxiv.org/html/2506.01242v2), especially B.2, C.1–C.3, C.6 and Figure 9. No third-party engine source was consulted.

## Implemented

- `gadget_build`: Resolve and Maxmargin root layers over **one** copied continuation forest. The two modes share continuation infosets and solver arrays. Roots within an opponent information set are sampled using normalized chance-times-our reach. Root-group Resolve probabilities use `0.5 * (normalized y(J) + 1/m)`; `y(J)` is counted once per infoset. An all-zero y vector falls back to uniform, explicitly.
- `gadget_blueprint_stats`: fixed-profile conditional continuation values and separate counterfactual/opponent reach arrays. This does not replace the opponent with an omniscient best response.
- `gadget_group_blueprint`: conditional values at a root group. Checks that the opponent's own sequence reach agrees across its histories, as perfect recall requires.
- Gift and new-world alternate helpers. **All utilities are player-zero values.** Figure 9 line 8 says `effective_alternate = u(x,y|J) - gift`. Both gadget continuations therefore use `raw_value - effective_alternate`. Resolve's centered exit value is zero. This yields the truncated-margin objective without changing its strategies. A nonzero-alternate analytic fixture catches a wrong offset sign.
- `kluss_select`: order-2 frontier closure from the current own-history infoset plus directly connected opponent-history groups. It does not take the transitive closure. Sorting/binary search costs O(R log R) for R frontier histories; forest copying is O(nodes + edges + roots).
- The retained downward closure leaves off-current-infoset player-zero nodes **unfrozen**. Their choices can improve in the next solve.
- `KlussBlueprint`: owned structural/history/behavior snapshot. No accumulated regret, last-regret prediction or average-strategy counts are transferred. `gadget_seed_blueprint` can seed fresh minimizers with the previous behavior as their initial policy.
- Explicit rejection of overlapping root subtrees, invalid probability distributions, zero counterfactual support, nonfinite inputs, and downstream opponent infosets that forget which root group they observed.

## Integration still required

This is a tested **generic core**, not an arena candidate. It is not linked into the current `gtcfr_decide`. The existing `src/cfr.h`, `src/belief.h`, `src/gtcfr.*`, evaluator and front end are unchanged.

1. Keep an opaque search context across actual moves. The current implementation frees `Tree` after each decision. A copied `Game` alone is insufficient: the adapter must also keep Position, both players' complete own-move/view history keys, raw leaf values, and root/action mappings for retained nodes.
2. Advance/filter the saved tree using the observations and our chosen move. Match a **history frontier**, not just a board. The order-2 closure must retain worlds outside our present infoset that remain possible to the opponent. A gadget over newly sampled own-belief worlds alone is not full 2-KLUSS.
3. Compute CF reaches from the saved strategy/tree. Learned posterior weights are not interchangeable with chance-times-our reach, and posterior group mass is not `y(J)`.
4. Compute group alternate values and path gifts before pruning. Copy the selected continuation and keep the returned node/infoset maps for board payload remapping. New samples have singleton opponent knowledge and alternate `min(eval, previous_value)` per Figure 9, explicitly marking that assumption.
5. Every newly expanded descendant must inherit its root group's utility offset. A raw evaluator value inserted directly into the centered tree is wrong. Restore raw values before capturing the next blueprint; do not subtract offsets twice on later turns.
6. Implement the paper's smooth Resolve/Maxmargin controller (Figure 10) with shared continuation updates. `gadget_mode` currently selects one exact gadget for correctness tests; it does **not** claim to implement that controller. Opponent root minimizers need their own updates, not arbitrary copying of accumulated regrets across objectives.
7. Enforce the whole-decision deadline, max-node/memory limits, and correct initial-leaf fallback. Run the requested 24 deaths + 24 survivals and five arena deaths with the same budgets, then paired 180+2 games. No strength claim before these gates.

The adapter must log: fraction of current histories present in the saved tree, new singleton fraction, size of I versus I², alternate/gift ranges, weighted and unweighted root coverage, mode/switch counts, setup/solve/expansion seconds, and fallback reason. The gadget cannot protect against a hidden attacker whose world never enters the retained/sample tree.

## Correctness checks

`make test_m4` runs:

- A 99% ordinary / 1% fatal world game. Plain expected-value PCFR+ chooses the risky action (value 0.98); both gadget variants choose the safe action with zero measured gadget exploitability.
- A game with unequal nonzero alternate values and an analytic 50:50 mixed equilibrium. Last-iterate output reaches 0.5; computed exploitability is numerical zero.
- An infeasible-margin game with different analytic answers: Resolve chooses action zero with probability 0.75; Maxmargin chooses 7/17. Both converge to numerical-zero gadget exploitability.
- Complete-frontier Kuhn poker: conditional blueprint alternate values, distinct hidden cards, full-game opponent best-response evaluation after replacing player zero's strategy. Both modes preserve the converged blueprint's 1/18 opponent BR value. This is a full-cut fixture, not a safety proof for truncated KLUSS.
- A counterfactual reach test where a zero-probability opponent action still has nonzero opponent-counterfactual support.
- A distance-two frontier world that must be excluded, an off-current-infoset node that must be re-optimized, deep-copy independence, and failed snapshot replacement preserving the old blueprint.
- Bad root/weight inputs and fresh solver-state checks.

Address/undefined-behavior/leak sanitizer runs cover `test_gadget` and `test_kluss`. The sandbox prevents LeakSanitizer's process inspection; the same binaries were therefore run on the host with leak detection enabled.

Generic exact gadget games have the usual conditional safety premises. Obscuro's approximate depth-limited 2-KLUSS does not inherit a general full-game safety guarantee (paper C.6). These fixtures establish arithmetic, topology and solver behavior, not chess Elo.
